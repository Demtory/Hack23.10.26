# Research: 003 — Панель маркетолога

Дата:2026-10-24. Исследование для плана, не реализация и не результат приёмки003.
Контекст: spec.md с ответомА, конституция1.0.0, исходники и отчёт002.
Исследовательские агенты изучили UI/навигацию и API/CSV только чтением.

## 1. Фактическая база

**Decision:** развивать текущие компоненты и транзакции, не создавать новый проект.
**Evidence:** App.tsx хранит page/selectedId локально; Dashboard.tsx — условия/страницу,
которые теряются при unmount. Settings.tsx не блокирует уход и обновляет лишь summary.
В CSS Inter объявлен, но локальных font files нет; заголовки serif; Settings содержит
inline тёмные цвета. ui.tsx уже содержит badges, числа/деньги, Spinner/ErrorBox/EmptyState.
api.py уже имеет согласованный bundle002 и общий выбор cookie/Bearer; PATCH не имеет
проверки исходной версии. Detail не содержит времени/контекста run. CSV/urgency отсутствуют.
Baseline002: в STATUS записано380 passed и успешные build/browser/Docker; эти проверки
в рамках планирования повторно не выполнялись. Это не доказательство готовности003.

## 2. Визуальные референсы

**Decision:** постоянная навигация, компактные фильтры над данными, глобальная сводка,
выбранная группа и детали различаются; без landing hero и вымышленных трендов.
**Rationale:** это поддерживает путь маркетолога «масштаб → приоритет → причина».
Публичная [страница Метрики](https://b2b.yandex.ru/adv/metrika) доступна; кабинет за
авторизацией не исследовался. Направление Aéza берётся из запроса и предыдущего
визуального исследования, зафиксированного в spec: [aeza.ru](https://aeza.ru).
Повторное чтение Aéza через web завершилось redirect loop; новый визуальный просмотр
не заявляется. После плана получен брендбук пользователя: он изучен и имеет
приоритет над прежним направлением сайта. Официальные HEX и роли шрифтов отделены
от наших UI-токенов в contracts/brand.md и contracts/ui.md. Приёмка впереди.

## 3. Компоненты и shadcn/ui

**Decision:** первый этап — существующий CSS и небольшие React-компоненты,
нативные button/input/select/table/dialog; без shadcn/Tailwind/Radix/Recharts.
**Rationale:** текущему стеку не требуется новая основа стилей для6 экранов и2 графиков.
shadcn совместим по подходу, но его Vite setup требует Tailwind/plugin/alias и
дополнительных компонентов: [официальный setup](https://ui.shadcn.com/docs/installation/vite).
**Alternatives:** полная интеграция shadcn отклонена по объёму, не из-за утверждения
о несовместимости React18; ручная разработка сложного select не нужна — native select.
Для native dialog отдельно проверить заголовок, Escape, начальный/возвращаемый фокус:
[MDN dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog).

## 4. Навигация

**Decision:** единственная новая runtime dependency — react-router-dom7.18.4,
createHashRouter/data router и useBlocker; без обновления React/Vite/FastAPI.
**Rationale:** Browser Back/Forward, прямой вход, защита черновика и восстановление
контекста требуют реальной истории. Hash позволяет сохранить текущий StaticFiles
без server-side SPA fallback и новых серверных путей. useBlocker покрывает SPA,
для reload/закрытия дополнительно beforeunload, без обещания собственного текста окна.
**Alternatives:** local page state не выполняет FR-005; самописный popstate/revert/go
guard сложнее и рискованнее библиотеки при быстрых переходах. BrowserRouter требует
настройки серверного fallback без пользы для выбранного объёма.
Источники: [createHashRouter](https://reactrouter.com/7.18.4/api/data-routers/createHashRouter),
[useBlocker](https://reactrouter.com/7.18.4/api/hooks/useBlocker),
[минимумы7.x](https://reactrouter.com/7.18.4/upgrading/v6),
[npm metadata](https://registry.npmjs.org/react-router-dom/7.18.4).
Проверены Node>=20 и peers React/ReactDOM>=18; локальный Node24.21.0 и Docker node22
подходят. Версия фиксируется при implement, не используется @latest и не обновляется major.
Контекст7 подтвердил требование data router для blocker.

## 5. Проверки интерфейса

**Decision:** единственная новая dev dependency — @playwright/test1.64.1,
Chromium E2E; без Vitest/jsdom/testing-library/axe на первом этапе.
**Rationale:** tsc не проверяет Back/focus/scroll/диалоги/две вкладки/скачивание.
Один framework покрывает реальные сценарии и управляемые задержки/ошибки.
[Документация](https://playwright.dev/docs/intro),
[npm metadata](https://registry.npmjs.org/@playwright/test/1.64.1): Node>=20.
Установка и загрузка браузера только при implement; недоступный browser не считать PASS.
Контраст и оценка3 участников остаются отдельными проверками, не подменяются screenshot.

## 6. Брендбук, шрифты, цвета и материалы

**Decision:** применять брендбук пользователя 2026: основной Exo 2, дополнительный
Inter для плотных данных/подписей; голубой #4CC6F1, чёрный #000000, фон #F4F4F4.
Дополнительные #182D48/#ECCFDB/#E97C35 не заменяют основную палитру.
Это явно заменяет раннюю гипотезу об основном Inter и оранжевом акценте.
Карта физических страниц PDF, SHA256, знак/поле/иконки/паттерн — contracts/brand.md.

**Evidence:** прочитан текст 43 страниц, визуально проверены ключевые страницы
логотипа, палитры, шрифтов, иконок и паттерна. Основной знак — четыре клавиши,
компактный é — отдельный подлинный вариант; оригинальные монохромные варианты
сохраняются. На схеме поле 30 px; UI принимает минимум 30 CSS px консервативно.
PDF-подмножества шрифтов не используются как полноценные webfonts. Inter 18pt —
не указание размера всех текстов и не новое выдуманное семейство.

**Delivery:** полные локальные файлы с кириллицей, font-display:swap, fallback и
отдельные лицензии: [Exo 2](https://github.com/google/fonts/tree/main/ofl/exo2),
[OFL Exo 2](https://raw.githubusercontent.com/google/fonts/main/ofl/exo2/OFL.txt),
[Inter](https://rsms.me/inter/). Материалы знака — утверждённый SVG или точный
векторный экспорт PDF с проверкой пропорций/paths/viewBox и manifest происхождения.
Никакого runtime CDN, npm-пакета ради шрифта, Unicode/AI/перерисовки вместо знака.
При невозможности точного экспорта конкретный материал остаётся блокирующим.

**Accessibility:** реальные непрозрачные пары рассчитаны по относительной яркости:
black/blue 10.655, navy/blue 7.067, white/blue 1.971, white/orange 2.838.
Основная голубая кнопка получает тёмный текст; значимые графики/иконки — контрастные
границы/контейнеры, текстовые альтернативы. Служебные статусы риска отделены от бренда.
Пороги [W3C](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
проверяются на actual styles, а не только в таблице токенов. Маскот не обязателен:
это наша адаптация аналитики, не запрет брендбука. Декор не имитирует историю/данные.


## 7. Срочность и согласованная выборка

**Decision:** общий WHERE q/level/urgency для count/items/top/CSV, EXISTS по исходной
services. asOf — из pinned run, даты/границы канонические UTC milliseconds.
**Rationale:** unknown может иметь исходную услугу, но пустой массив оценённых услуг
в detail. Фильтрация detail.services потеряла бы такого клиента. EXISTS не дублирует
клиента с несколькими услугами. Не использовать часы браузера и julianday float для
границ ±1ms. Никакой перераздачи балансов или пересчёта формул ради фильтра.
**Alternatives:** фильтр страницы и цикл загрузки всех JSON-страниц отклонены.
Индекс добавлять лишь после измерения, новая схема/таблицы здесь не нужны.

## 8. CSV и точность

**Decision:** серверный csv.writer, UTF-8 BOM, comma, CRLF, QUOTE_ALL, один header;
метаданные повторяются колонками каждой строки. Деньги — точные decimal strings
из INTEGER cents, без euros()/JSON float/JS Number. Не добавлять XLSX или ZIP.
**Rationale:** 9007199254740993 cents должны дать90071992547409.93 EUR;
max int64 —92233720368547758.07. Обычное открытие CSV редактором может округлять
числа/ID; для точного просмотра больших значений требуется импорт колонок как текст.
Parser проверяет байты, но не доказывает поведение редактора.
CSV фиксирует runId увиденной выборки; если latest уже иной —409 и обновление списка.
Старый run нельзя JOIN к текущим accounts/services: источник не версионирован.
Материализация bytes в одном read snapshot до HTTP200, Blob — после полного чтения.
Источники: [SQLite transactions](https://www.sqlite.org/lang_transaction.html),
[Python csv](https://docs.python.org/3/library/csv.html).

## 9. Безопасность CSV

**Decision:** кавычки csv.writer плюс документированное обратимое text:-кодирование
опасного пользовательского текста email/filter_q; числовые столбцы не преобразуются.
Правило/пограничные строки определены в contracts/api.md. Никаких Excel-формул для
сохранения длинных чисел. Нужна проверка parser и доступного табличного редактора.
**Rationale:** quoting не предотвращает formula injection. OWASP предупреждает об
отсутствии универсального CSV sanitization для всех редакторов и повторных сохранений:
[CSV Injection](https://community.owasp.org/attacks/CSV_Injection).
**Alternatives:** один apostrophe/tab-prefix без оговорок ненадёжен; универсальную
безопасность произвольного стороннего редактора не обещаем. text: сохраняет опасную
строку как видимый текст; исходный снимок не меняется, формат обратим при разборе.

## 10. Конфликт настроек и неопределённый исход

**Decision:** optional strict expectedVersion в PATCH; новый UI передаёт всегда.
Сравнение внутри прежнего BEGIN IMMEDIATE до записи;409 не меняет состояние.
Без поля/null прежняя null-omission/legacy семантика сохранена. Защита относится к
новому UI/условным запросам, а не обещает запрет всем старым внешним writers.
Любой успешный legacy PATCH повышает version и инвалидирует старый UI-черновик.
На409 сохранять draft/baseVersion; запрещён automatic rebase/force overwrite.
При потере ответа после возможного commit — uncertain, перечитать состояние,
но совпадение значений не доказывает успех именно нашего запроса. Авто-retry нет.
Явная загрузка текущего требует отказа от черновика; подробности в data-model/контрактах.
**Alternatives:** только disabled button допускает race; обязательная precondition
для всех старых consumers нарушила бы согласованную совместимость002.

Все исследовательские вопросы разрешены решениями выше; пользовательские требования
не расширены. Точные компоновки/контракты представлены в плановых артефактах,
их фактическая работоспособность проверяется после реализации.
