# UI contract / визуальная приёмка003

План оформления/поведения, не реализованные экраны. Основание: spec US1–US6,
FR-001–FR-023. Сохраняем данные/формулы/сценарии001/002; каждый контроль ниже
получает реальное подтверждение в implement, а не галочку за существование CSS.

## 1. Компоновки6 экранов

| Экран | Иерархия и основные действия |
|---|---|
| Вход | Компактная светлая форма, название продукта, email/password с labels, видимая ошибка/ожидание, прежний login. Без рекламного hero и выдуманной статистики |
| Сводка (Dashboard) | Header и времена →4 KPI (ожидаемые потери/платежи под риском/уровни/покрытие) →распределение уровней и топ5 →переход к списку. Вся страница глобальная |
| Клиенты | Заголовок и число совпадений →поиск/уровень/срочность →active chips/сброс/экспорт →компактный топ выбранной группы →таблица и pagination. Таблица/топ/число — одна выборка |
| Карточка | Breadcrumb/back →клиент/score/уровень/полнота →главные причины и отдельные floors/bonus/cap →денежная оценка и её границы →услуги с точными сроками/периодами. Ошибка404 сохраняет путь назад |
| Настройки | Applied version/dirty indicator →веса/пороги/денежные параметры с корректными пояснениями →явные Save/Reset →реальные результаты применённой модели; диалог ухода и предупреждение конфликта |
| Данные | Контекст/даты →количества записей →download raw JSON →полная замена snapshot с пояснением и состояниями. Без изменения формата/raw transport002 |

Боковая навигация: Сводка/Клиенты/Настройки модели/Данные, текущий пункт aria-current,
выход и реальный статус получения данных. На малой ширине та же навигация в drawer.
Раздел данных и настройки не скрываются ради эстетики. Заголовки и формы единообразны.

Основная кнопка остаётся голубой; hover/active задаются контрастной границей/состоянием,
а не произвольной сменой фирменного цвета. Disabled не используется для важных подписей.
Расчёт контраста: black/blue 10.655; navy/blue 7.067; navy/gray 12.663;
black/gray 19.093; black/orange 7.399; navy/white 13.928; navy/pink 9.627;
control-border/white 4.542 и /gray 4.130. Белый/голубой 1.971 и белый/оранжевый 2.838
не подходят для значимого текста/границ. Цветные графики имеют тёмные разделители
и подписи. Проверить actual computed styles, прозрачности, hover/focus/error;
декоративная граница не заменяет важную. Пороги — FR-020 и
[W3C](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

Полные шрифты с кириллицей и отдельными лицензиями размещаются в public/fonts,
font-display:swap; Inter 18pt не означает глобальный размер текста 18pt.
Проверить загрузку обоих семейств, начертания и fallback без CDN.
Убрать serif headings и тёмные inline Settings styles, а не скрывать их root variables.

BrandLogo использует подлинный монохромный полный/компактный SVG, BrandIcon —
заливные UI-иконки со скруглениями. Логотип не перерисовывается, не красится и не
получает тени. Поле 30 CSS px сохраняется вокруг видимой формы; компактный блок
с 24 px знаком имеет min-height 84 px и растёт при увеличении текста.
Название продукта отдельно от знака. Favicon — подлинный компактный é без счётчика.
Паттерн только в свободной бренд-зоне входа; маскот не обязателен.


## 3. Компоненты и семантика

Переиспользовать components/ui.tsx: badge labels, money/number/plural, ErrorBox,
EmptyState/Spinner; расширить небольшими Button/Card/Field/Notice/PageHeader/Dialog.
Не создавать generic design-system framework. Native select вместо сложного combobox.
Из Dashboard извлечь RiskDistribution/LossRanking и CustomerTable; данные через props,
внутри графиков не должно быть независимых fetch/локального ранжирования страницы.
ClientFilters владеет контролами/chips, но источник состояния — ClientContext.
CalculationContext показывает3 различающиеся даты и last successful read при необходимости.

Table: caption/thead/th scope=col, sort button с aria-sort наth, видимые единицы;
клиент — настоящий link, а не только click наtr. Email длинный переносится/обрезается
с доступным полным текстом. Unknown score —«—/Нет оценки», не0. Статусы имеют текст.
Graph: доступное название/описание и текстовый список значений, интерактивность links/buttons;
цвет не единственный носитель. Нулевой total —empty state без деления на0; нулевые потери
не равны отсутствию клиентов. Оба графика отвечают вопросам из FR-003, тренды отсутствуют.
Native dialog: accessible title, первый безопасный фокус «Остаться», Escape=отмена,
фон недоступен, после закрытия фокус на trigger; drawer использует те же правила.

## 4. Выборка и навигация

/#/overview, /#/customers, /#/customers/:id, /#/settings, /#/data, /#/login.
Прямой hash/reload работает через существующую статику. Условия списка хранятся в
session UI context/history state; изменения фильтра заменяют текущую запись,
не создают Back для каждого введённого символа. Переходы раздел/карточка добавляют history.
Вход в Клиенты из sidebar восстанавливает последний контекст текущей сессии.
Явный клик на глобальном распределении создаёт выборку выбранного level без скрытых
прежних q/urgency (page1, сортировка сохраняется). Это намеренное новое условие.
Клик на топ сводки сохраняет origin=overview; back возвращает туда и на исходный link.
Обычное открытие из таблицы сохраняет условия/page/scroll/customerId; restoration
после данных, не до fetch; восстановить и scrollLeft контейнера таблицы. Не заменять Browser Back искусственным всегда-to-list.
При прямой карточке без origin fallback «К списку» с defaults, без фиктивной истории.

После logout/нового входа Browser Back не восстанавливает поиск/условия/фокус
предыдущего пользователя или завершённой UI-сессии: restore points имеют owner,
проверяемый до применения history.state (data-model.md).

Меняется запрос фильтров →table/top loading, не выдавать старый набор за новые условия.
Live refresh того же запроса →последний целый bundle+«Обновляем», без ложных нулей.
CSV недоступен до завершения запроса и при total0; фиксируются условия отображённого
bundle и runId. Изменение фильтров во время экспорта не меняет captured operation.
Сброс очищает q/level/urgency иpage1, сохраняет sort/order. Active chips удаляются отдельно.
Сроки считаются от server asOf; UI подписывает вложенность48h/7d и точный timezone.
Срочность отбирает клиентов с подходящей услугой, но денежные показатели остаются
по всем оценённым услугам клиента; это не сумма только платежей выбранного интервала.

## 5. Честные подписи и состояния

«Полнота данных» вместо «Уверенность/точность». Score0–100 — экспертная оценка,
не обученная вероятность. Деньги —«Эвристическая оценка потерь при ближайших платежах»;
периоды разных услуг не выдаются за единый месяц. Unknown money0 сопровождается
отсутствием оценки, не обещанием безопасности. Явный price0 показывается как0EUR,
не подменяется пропуском; ограничения оценки при нулевой цене объясняются отдельно.
Drivers услуги и customer rules не складываются как одинаковые клиентские баллы.
Для экранов использовать Intl.DateTimeFormat с часовым поясом браузера и явным
  timeZoneName; в тестах UTC и Europe/Moscow должны показывать один момент без
  изменения результата фильтра. CSV сохраняет ISO UTC. Показывать asOf/updatedAt
  с timezone; источник —«Дата исходных данных неизвестна».
Результаты в Settings подписаны применённой версией, не являются preview draft.

Шесть экранов: initial loading/error/empty/success; для поиска отдельно nothing found,
для оценки unknown. Ошибка —понятный следующий шаг и retry, не rawJSON/stacktrace.
Settings: dirty/saving/saved/validation_error/conflict/uncertain по data-model.md;
reset —локальныйdraft, Save —один guarded запрос с заблокированными редактируемыми полями, stay/discard подтверждают уход.
Связь: SSE, резервный опрос, offline/stale и последнее успешное получение различаются;
не выдавать просто открытый EventSource за актуальные данные.401 скрывает protected UI.
