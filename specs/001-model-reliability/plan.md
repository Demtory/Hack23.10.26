Скрипт Spec Kit сообщает логическое имя функции `001-model-reliability`; фактическая Git-ветка — `feature/risk-desk`. Переключение и создание веток в планирование не входят.

## Summary

Развить существующий прототип в трёх направлениях: устойчивые конечные расчёты, атомарное изменение настроек/снимка вместе с результатами, объяснения фактически применённых правил. Неполный снимок отклонять целиком; сохранить явные нули, false и согласованную PATCH-семантику null. Не менять формулу риска на обычных полных данных.

Транзакцией управляет вызывающая операция, вспомогательные функции не фиксируют её самостоятельно. Дополнительные причины хранятся в существующем JSON и возвращаются отдельным `explanationRules`; смысл `drivers` сохраняется. Реализация не начата. Этот документ заканчивает проектирование; `tasks.md` создаётся отдельным навыком.

**Scale/Scope**: три ошибки аудита и непосредственно связанные отказы/restart/совместимость. Редизайн, shadcn/ui, OIDC, история, таймер и остальные замечания аудита исключены.

## Этапы реализации

1. **Валидация и устойчивый расчёт.** В schemas.py задать конечные числовые параметры и обязательность полей снимка; в api.py проверять объединённые настройки. В scoring.py сохранить штатную арифметику, добавить устойчивую сигмоиду и резервное нормирование больших весов. В main.py безопасно сериализовать ошибки валидации с неконечным input. Закрепить три исходных воспроизведения и контроль 75/551.
2. **Общая атомарная операция.** Убрать внутренние commit/rollback и контекст фиксации у helpers; перед чтением/изменением начать явную транзакцию, выполнить проверку, запись, пересчёт и подготовку сериализуемого ответа, затем один commit. Охватить PATCH, PUT, старт и пересчёт при отсутствии кэша. Сохранить пустой принятый снимок при restart.
3. **Объяснения без изменения модели.** Зафиксировать фактические переходы оценки в момент расчёта; хранить их в detail JSON; добавить контракт и отображение в карточке. Исправить summaryText с учётом итогового level/unknownReason. Прежние drivers не расширять псевдовкладами.
4. **Совместимость и документация.** Проверить старую БД/настройки, full raw/demo, все сортировки, авторизацию, деньги, метрики, SSE. Затем точечно обновить затронутые документы и сгенерировать OpenAPI. Реализация и подтверждение этих этапов — следующая работа.

## Риски и ограничения

| Риск | Предотвращение / проверка |
|---|---|
| Скрытые commit, включая nested with conn и default settings | Проверить все вызовы; один владелец на каждый путь записи; поздняя fault injection, включая отказ commit до успешной фиксации с последующим rollback |
| Валидация возвращает 500 из-за NaN внутри описания ошибки | Безопасный detail без несериализуемого input/ctx; raw payload-тесты |
| FastAPI response_model отфильтрует существующие поля | Полный DTO только затронутого detail; контрактная сверка всех прежних полей и значений |
| Новый текст незаметно меняет арифметику/округление | Штатный путь суммирования сохранить; регрессии обычных fixtures и 75/551 |
| Пустая БД после намеренной очистки ошибочно получает demo | Признак инициализации — аккаунты либо сохранённый score_run; restart-тест |
| Блокировка SQLite при BEGIN IMMEDIATE | Существующий timeout, контролируемый отказ без частичной записи; без новой системы конкурентного редактирования |
| Технический предел INTEGER и большие денежные итоги | Проверять представимость входа/результата, отклонять без commit; не вводить произвольный бизнес-потолок и не менять денежные типы |
| Сеть оборвалась после commit | Не обещать откат доставки HTTP; проверка сохранённого состояния повторным GET |
| Исторические нули уже потеряли происхождение | Не придумывать восстановление; не сбрасывать старую БД |
