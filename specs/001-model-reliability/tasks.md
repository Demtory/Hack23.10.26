## Формат и правила выполнения

`- [ ] TNNN [P?] [USn?] действие с конкретными файлами и критериями`.

[P] означает возможность выполнения одновременно с указанной ниже независимой задачей после её общих предпосылок. Это не разрешение запускать соседние задачи без проверки зависимостей. US1–US3 соответствуют историям спецификации, все имеют приоритет P1. Пути ниже отсчитываются от корня репозитория.

Тесты обязательны по FR-022 и конституции. Сначала воспроизвести дефект: новый негативный регрессионный тест должен падать по ожидаемой причине на старом поведении; положительные проверки уже работающих сценариев могут проходить сразу. После исправления прогнать связанные проверки повторно. Падение установки/импорта не считается воспроизведением дефекта.

Тесты изменяют только временную SQLite с фиксированным as_of и синтетическими данными. Перед изменением файла прочитать его текущую версию; не перезаписывать параллельные правки. Флажок закрывается после указанной проверки и фиксации её фактического результата.

## Dependencies & Execution Order

### Порядок фаз

```text
T001 → T002 → T003 → US1: T004–T017 (первый инкремент)
                              ├→ US2: T018–T026
                              └→ US3: T027–T032
US1 + US2 + US3 → T033–T038 → итоговая приёмка
Тесты историй можно готовить независимо после T003; интеграция ждёт US1.
```

Граф отражает логические предпосылки историй, а не разрешение одновременной правки одинаковых файлов. Рекомендуемый безопасный порядок реализации: US1 → US2 → US3 → итоговая приёмка. Все три истории P1; US1 первая, потому что защищает последующие операции от повреждения состояния.

### Зависимости задач

- T004/T005/T006 после T003 независимы по файлам. T007 после T006: один файл. При создании fixtures каждый тест использует T003.

## Implementation Strategy

1. Подготовить среду и зафиксировать baseline (T001–T003).
2. Первый минимальный полезный инкремент — US1: числа, атомарность, restart. Подтвердить T017 перед расширением поведения.
3. Добавить US2 на полном demo, проверить API и видимые причины в карточке.
4. Добавить US3, подтвердить матрицу полноты и сохранение явных0/false, повторить связанный rollback/restart.
5. Выполнить T033–T038. Никакие другие замечания аудита и следующий этап проекта сюда не переходят автоматически.
