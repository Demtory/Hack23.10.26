# Feature Specification: График оттока — факт и прогноз

**Feature Branch**: `main` — по просьбе команды.

**Created**: 2026-10-24

**Status**: Implemented — закрывает последний бонусный пункт кейса
(«График оттока: услуги под риском, предстоящие непродления, исторические удаления;
факт и прогноз должны быть различимы»).

**Input**: Кейс даёт дополнительные баллы за график оттока. В данных нет даты удаления,
поэтому исторический ряд восстановить нельзя — нужно показать то, что вычислимо,
и честно обозначить границу.

## User Scenarios & Testing

### User Story 1 — Понять, когда наступит отток (Priority: P1)

Маркетолог открывает «Сводку» и видит, сколько услуг уже не продлено и сколько
непродлений ожидается в следующие 30 дней, с деньгами.

**Acceptance Scenarios**:

1. **Given** сводка, **When** открыт блок «Когда наступает отток», **Then** слева видны
   столбцы факта, справа — прогноза, они различаются цветом и легендой.
2. **Given** блок, **When** пользователь наводит на столбец, **Then** видит дату,
   количество услуг и ожидаемые потери/клиентов.
3. **Given** блок, **When** прочитано примечание, **Then** понятно, что исторических
   удалений нет и почему.

### User Story 2 — Не перепутать факт с прогнозом (Priority: P1)

**Acceptance Scenarios**:

1. **Given** любой столбец слева, **When** он относится к прошлому, **Then** это услуги
   со сроком ≤ среза, которые ещё не удалены.
2. **Given** любой столбец справа, **When** он относится к будущему, **Then** это
   ожидаемые непродления, а не свершившиеся удаления.

### Edge Cases

- Все услуги удалены → прогноз и факт нулевые, ошибок нет.
- Услуга с ценой 0 → попадает в счётчик услуг, но не в деньги.
- Клиент без оценки → его услуг в деталях нет, в прогноз не попадает.
- Окно 30 дней, срез фиксирован `AS_OF` → ответ детерминирован.
- Услуга истекла утром дня среза → попадает в факт текущего дня.

## Requirements

- **FR-001**: `GET /api/v1/analytics/forecast` MUST требовать аутентификацию.
- **FR-002**: Ответ MUST содержать `fact`, `forecast`, `totals`, `asOf`, `pastDays`,
  `horizonDays`, `note`.
- **FR-003**: Факт MUST включать услуги с `expiresAt ≤ asOf` и статусом не `deleted`.
- **FR-004**: Прогноз MUST включать услуги с `asOf < expiresAt ≤ asOf + horizonDays`;
  ожидаемое число непродлений — сумма P(score), потери — сумма P×price×(1−mitigation).
- **FR-005**: `pastDays` и `horizonDays` MUST ограничиваться 1…90, иначе 422.
- **FR-006**: UI MUST различать факт и прогноз цветом, легендой и подписями.
- **FR-006a**: UI MUST показывать три величины из бонусного пункта кейса: количество
  услуг под риском, предстоящие предполагаемые непродления и факт истёкших услуг;
  исторические удаления не строятся, причина указана (FR-007).
- **FR-007**: UI MUST показывать примечание об отсутствии дат удаления.
- **FR-008**: Изменения MUST NOT менять формулы score и существующие контракты.

## Success Criteria

- **SC-001**: `pytest` → 431 passed (+9 новых).
- **SC-002**: Ответ детерминирован при одинаковых параметрах.
- **SC-003**: Суммы по дням совпадают с `totals`.
- **SC-004**: Блок виден на 1440 и 390 px без горизонтального скролла.
- **SC-005**: `openapi.json` содержит 16 путей.

## Assumptions

- Даты удаления услуг в исходных данных отсутствуют; «исторические удаления» не
  восстанавливаются и не имитируются.
- Ожидаемое число непродлений — сумма вероятностей, а не целое число.
