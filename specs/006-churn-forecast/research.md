# Research: график оттока без исторических данных

## R1. Что считать «историей»

**Решение:** исторических удалений не показывать. В данных отсутствует дата удаления
услуги, статус `deleted` без даты не позволяет построить ряд. Вместо вымысла — `note`
в API и подпись в UI.

**Альтернативы:** дата удаления из последней транзакции (не равна удалению),
«сегодня минус N дней» для всех удалённых (ложь), дозаполнение нулями (выглядит как
реальный спад) — отклонены.

## R2. Что показывать вместо истории

**Решение:** факт по снимку — услуги с истёкшим сроком, которые ещё не удалены
(то есть не продлены), и прогноз — услуги с истечением впереди, взвешенные P(score).

**Почему:** это два честно вычислимых ряда, и они отвечают на вопрос «когда наступит
отток», не притворяясь статистикой.

## R3. Где считать

**Решение:** на бэкенде, по сохранённым деталям последнего расчёта; формула
вероятности переиспользуется из `scoring.probability`.

**Почему:** фронтенд не знает формул; ответ детерминирован и тестируется без браузера.

## R4. Окна и валидация

**Решение:** `pastDays` и `horizonDays` — 1…90, по умолчанию 30; окно факта включает
день среза (услуга могла истечь утром).

## R5. Визуализация

**Решение:** CSS-столбцы без новых зависимостей; факт — тёмный, прогноз — голубой
с обводкой; подписи начала, среза и конца; итоги под графиком; примечание рядом.
