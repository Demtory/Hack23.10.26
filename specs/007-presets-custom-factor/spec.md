# Feature Specification: готовые наборы весов и свой коэффициент

**Feature Branch**: `main` — по просьбе команды.

**Created**: 2026-10-24

**Status**: Implemented

**Input**: Настройки модели слишком сложные: семь ползунков и пороги без готовых
вариантов. Нужны кнопки готовых настроек, возможность сохранить свой набор весов
и добавить собственный коэффициент в модель. Плюс поправить отступ у заголовка
признака и плашки «доля в модели».

## User Scenarios & Testing

### User Story 1 — Применить готовый набор весов (Priority: P1)

1. **Given** страница «Настройки модели», **When** она открыта, **Then** над весами
   виден блок «Наборы весов» с четырьмя готовыми вариантами.
2. **Given** блок пресетов, **When** нажат «Деньги важнее», **Then** веса черновика
   заполняются значениями набора, показан статус «Применён набор…», результаты
   пересчитываются только после «Сохранить».
3. **Given** применённый пресет, **When** нажато «Сохранить», **Then** версия модели
   растёт, клиенты пересчитаны, а пороги и денежные правила не меняются.

### User Story 2 — Сохранить свой набор (Priority: P1)

1. **Given** отредактированные веса, **When** «Сохранить как набор» и введено имя,
   **Then** набор появляется в списке и сохраняется на сервере (переживает рестарт).
2. **Given** свой набор, **When** «×» и подтверждение, **Then** набор удаляется,
   настройки модели не меняются.
3. **Given** имя занято или совпадает со встроенным, **When** сохранение, **Then**
   понятная ошибка 409; пустое имя, неизвестный признак или вес вне 0…1 — 422.

### User Story 3 — Седьмой признак модели (Priority: P1)

1. **Given** старые настройки, **When** приложение запускается, **Then** появляется
   `auto_off_share` с весом 0 и версия настроек растёт; прежние оценки не меняются.
2. **Given** вес 0, **When** клиент оценён, **Then** score совпадает с прежним (89,0).
3. **Given** вес 0,2, **When** клиент оценён, **Then** score меняется (85,9), а в
   причинах появляется «Без автопродления 67% услуг».

### Edge Cases

- У аккаунта все услуги удалены → доля 0, признак не влияет.
- Услуги с ценой 0 не ломают расчёт доли.
- Пользовательских наборов не больше 20; имена уникальны без учёта регистра.
- Встроенные наборы нельзя удалить (404).

## Requirements

- **FR-001**: API MUST отдавать список наборов: встроенные + пользовательские.
- **FR-002**: Пользовательский набор MUST храниться на сервере и переживать рестарт.
- **FR-003**: Создание MUST валидировать имя (1…40), веса (числа 0…1, известные
  признаки, хотя бы один > 0) и уникальность имени; ошибки 409/422.
- **FR-004**: Удаление MUST работать только для пользовательских наборов.
- **FR-005**: Набор MUST менять только веса; пороги и денежные правила — нет.
- **FR-006**: Новый признак MUST быть объявлен поколением настроек с весом 0,
  чтобы старые расчёты не менялись.
- **FR-007**: Заголовок признака и плашка «доля в модели» MUST быть визуально разделены.

## Success Criteria

- **SC-001**: `pytest` → 449 passed.
- **SC-002**: e2e → 10 passed, включая применение и сохранение набора.
- **SC-003**: `openapi.json` содержит 20 путей.
- **SC-004**: При весе нового признака 0 оценки клиентов не меняются.

## Assumptions

- Пресеты — про веса; пороги остаются ручной настройкой.
- Новый признак включается вручную: по умолчанию вес 0, чтобы не переписывать
  уже показанные результаты.
