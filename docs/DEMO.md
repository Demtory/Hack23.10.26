# Демо на 5 минут

> Репетировать с таймером. Один человек говорит, второй кликает.
> Всё, что не влезло, — в бэкап-видео.

## Подготовка (за 10 минут)

```bash
cd Hack23.10.26
git switch feature/risk-desk
docker compose down -v
docker compose up --build -d
curl http://localhost:8000/healthz
```

Открыть http://localhost:8000, войти `admin@example.test` / `admin123`.
Проверить, что на «Обзоре»: `3` высоких, `€21.56` ожидаемых потерь.
Если порт 8000 занят: `docker ps`, остановить старый контейнер,
`docker compose down && docker compose up -d`.

## Сценарий

### 1. Обзор — 40 секунд
- «Это кабинет решений, а не дашборд ради графиков».
- Три времени: данные на 23 окт., загружено, пересчитано.
- `3` высоких, `€21.56` под угрозой, `€67.53` платежей под риском.
- «Кто даёт потери» — user-0006 первый.

### 2. Рейтинг — 40 секунд
- Сортировка по балансу ↑/↓, по потерям.
- Фильтр «Высокий».
- Открыть `user-0006`.

### 3. Клиент — 60 секунд
- Score 89, уровень «Высокий».
- Одно предложение: `service-0006: продление через 2 дня, баланса €3.00 не хватает на €5.50`.
- «Следующее действие: Напомнить пополнить».
- Раскрыть «Детали расчёта»: статус, минимум, бонус — без технического шума.
- Услуги: 3 строки, статусы, сроки, score.

### 4. Модель — 60 секунд
- Формула `100 × Σ(w × f) / Σw`.
- «Веса относительные, сумма не обязана быть 1, 0 отключает признак».
- Показать долю влияния у «Нехватки денег»: 25%.
- Поднять вес до `0.60`, сохранить.
- «Пересчитано» обновилось, цифры на «Обзоре» изменились без reload.
- Перезапуск: `docker compose restart`, настройки на месте (можно не показывать вживую, сказать).

### 5. Данные — 40 секунд
- Показать «Данные на / Загружено / Пересчитано».
- Загрузить `data/raw/data.json` (или заранее подготовленный изменённый файл).
- «Загружено» изменилось, модель пересчиталась.
- Не обещать историю удалений: в данных нет дат удаления.

### 6. Метрики — 30 секунд
```bash
curl -s localhost:8000/metrics | grep -E 'churn_(customers_total|expected_loss_eur|amount_at_risk_eur)'
```
- Цифры совпадают с UI.
- `curl -s -o /dev/null -w '%{http_code}' localhost:8000/api/v1/customers` → `401`.

## Если что-то падает

1. Не перезагружать страницу и не чинить вживую.
2. Сказать: «Покажу на записанном демо», включить бэкап.
3. После демо — `docker compose logs --tail=100`.

## Вопросы жюри и ответы

- **Почему не ML?** В данных нет истории статусов и меток; обучать не на чем.
  Модель экспертная, объяснимая, с настраиваемыми весами.
- **Почему баланс снижает потери только на 50%?** Он закрывает ближайший
  платёж, но не удерживает клиента; будущая выручка всё равно теряется.
- **Почему не Postgres?** Кейс требует Docker Compose; SQLite проходит
  приёмку и 250 тестов. Postgres — отдельный этап после сдачи.
- **Что с историческим графиком?** В данных нет дат удаления; можем накапливать
  собственные снапшоты и прогнозировать непродления по `expiresAt`.
