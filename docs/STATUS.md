## OIDC / SSO (2026-10-24)

- Добавлен вход через OIDC: Authorization Code + PKCE (S256), state/nonce в БД
  (`oidc_flows`), одноразовое использование, TTL 10 минут.
- ID token проверяется по JWKS: подпись RS256, `iss`, `aud`/`azp`, `exp`/`iat`/`nbf`
  с допуском 30 секунд, `nonce`, наличие `sub` и подтверждённого email.
- Новых зависимостей нет: discovery, обмен кода и проверка RSA — стандартная библиотека.
- Первый вход создаёт пользователя по email (`password_hash` пустой, `oidc_subject`
  заполнен); парольный вход для такого пользователя невозможен. Прежний
  `admin@example.test` работает как раньше.
- `OIDC_INTERNAL_BASE` отделяет публичный issuer от внутреннего адреса провайдера —
  нужно, когда приложение в Docker ходит в Keycloak по имени сервиса.
- Keycloak для демо: `docker compose -f compose.yaml -f compose.sso.yaml up --build`, realm `risk-desk`,
  пользователь `marketer@example.test` / `marketer123`. Без профиля приложение
  работает только с паролем.
- Ошибки провайдера не ломают вход: пользователь возвращается на `/#/login`
  с понятным сообщением (`provider_unavailable`, `state_invalid`, `token_expired` и т.д.).
