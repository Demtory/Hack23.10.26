## Model reliability — приёмка 2026-10-24

Согласованные задачи `specs/001-model-reliability/tasks.md` выполнены. Этот раздел
подтверждает выбранную доработку и сохранение затронутых сценариев; он не заменяет
аудит всего кейса и не подтверждает остальные отложенные возможности проекта.

### Что изменено

- Настройки проверяются целиком после merge. NaN/Inf/нечисла возвращают безопасную422;
  midpoint10000 и очень малая положительная steepness рассчитываются устойчиво.
- Источники/настройки/результаты фиксируются одной транзакцией. Проверяются rollback
  при ошибках расчёта, SQL, сериализации, DTO, блокировки и commit до его успеха.
- Полный снимок обязателен, пропуски/null не заменяются достоверными0/false.
  Явные нули/false допустимы; намеренно пустой снимок не заменяется seed после restart.
- Отдельные explanationRules показываются в карточке даже при drivers=[];
  минимумы/бонус/cap и округление объяснений соответствуют итоговому score.
- Старый detail JSON без explanationRules читается как[]; валидные настройки
  и данные сохраняются. Новых SQL-таблиц, runtime-зависимостей и стека нет.

```bash
npm --prefix frontend ci --cache /private/tmp/risk-desk-npm-cache
npm --prefix frontend run build
PYTHONPATH=backend python scripts/export_openapi.py
```

- Итог: **246 passed**, один deprecation warning Starlette/httpx. Сборка React/TypeScript успешна.
- До исправления новые US1-проверки:24 failed/24 passed, US2:9 failed/1 passed,
  US3:11 failed/54 passed; причины падений соответствовали исправляемому поведению.
- Три ошибки аудита воспроизведены до исправления и закрыты: midpoint10000 + restart;
  high78 с пустым drivers и видимыми минимумами70/+8; неполный снимок отклоняется422.
- Контроль75/551; значения score/level/confidence/drivers/money и summary для seed/raw
  на стандартных настройках дополнительно сопоставлены с исходным scoring из HEAD:
  совпадают. Текст объяснений сравнивался отдельно, поскольку это исправляемое поле.
- Все обязательные поля проверены на omission/null,0/false; история неизвестна при
  отсутствии транзакций, score возможен при достаточности других признаков.
- Неизменность данных/version/updatedAt/runs после отказа проверяется новым соединением;
  следующий корректный запрос и restart успешны. Есть отдельные проверки startup,

- Проверены8 сортировок по всем страницам, login/logout/401, raw10/30/100 и demo,
  равенство количеств/денег списка, деталей, summary и метрик.
- Во встроенном браузере: клиент5 high78, drivers=[], видны минимумы70 и+8;

  успешные PATCH/PUT дают новые runId3→4→5, отказ PUT422 нового события не даёт.
  Проверены метрики и загрузка raw. Отдельный настоящий перезапуск процесса с тем же
  временным файлом сохранил midpoint10000 и пустой снимок при SEED_ON_START=true.
- OpenAPI:11 путей, прежние пути сохранены; required/nullable и explanationRules
  проверены тестом. Повторный экспорт побайтово совпал. git diff --check успешен.
- Тестовый сервер остановлен; временные браузерные вкладки закрыты. Рабочие данные,
  секреты, конституция и согласованные требования не изменялись. Commit/push не выполнялись.

### Что не проверено / ограничения

- Новый Docker-образ не собирался: проверены Python3.12/uvicorn и production frontend build;
  Dockerfile/compose и runtime requirements не менялись. Чистый контейнерный запуск
  этой редакции отдельно не подтверждён.
- Внешний комплект «Практика» и реальные/внешние сервисы не использовались;
  проверки относятся к синтетическим raw/demo репозитория и временным БД.
- Встроенный Playwright connector не нашёл Chrome, а запуск headless Chromium
  ограничен macOS sandbox. UI проверен через доступный встроенный браузер;
  отдельного нового frontend test framework не добавляли.
- Исходный npm audit сообщает2 уязвимости (moderate/high), а Starlette предупреждает
  о будущем переходе TestClient на httpx2. Общее обновление зависимостей вне объёма.
- Не добавлены восстановление уже повреждённой БД, восстановление происхождения
  исторических нулей и остальные отложенные замечания аудита.
