# Демо-стенд

Публичная копия проекта на VPS Aéza — чтобы жюри могло открыть приложение без
Docker и GitHub.

**Адрес:** <http://193.233.246.179:8000>
**Вход:** `admin@example.test` / `admin123` — как написано на экране входа.
Данные на стенде тестовые; стенд публичный, после защиты его можно снести.

## Что за сервер

| Параметр | Значение |
|---|---|
| Хостинг | Aéza, тариф MSKs-2 |
| IP | `193.233.246.179` |
| ОС | Ubuntu 26.04 LTS, x86_64 |
| Ресурсы | 2 vCPU, 3.9 ГБ RAM, 53 ГБ диска |
| Docker | 29.1.3, Compose 2.40.3 |
| Каталог | `/opt/risk-desk` |
| Том данных | `risk-desk_app-data` (SQLite) |
| Порт | 8000 (наружу), 22 (SSH) |

Стенд поднимается одной командой `docker compose up -d --build`, контейнер
с `restart: unless-stopped`, Docker включён в автозапуск — после перезагрузки
сервера всё встаёт само.

## Обновить стенд

Из локального репозитория:

```bash
./scripts/deploy_remote.sh          # rsync + пересборка + статус (без Keycloak)
SSO=1 ./scripts/deploy_remote.sh    # то же + Keycloak и снятие HTTPS с консоли
```

Скрипт копирует рабочее дерево (без `.git`, `.venv`, `node_modules`, базы и `.env`),
затем пересобирает образ и перезапускает контейнер. Пароли и `.env` остаются
на сервере и в git не попадают.

Другой сервер: `./scripts/deploy_remote.sh root@1.2.3.4`.

## Полезные команды

```bash
ssh -i ~/.ssh/risk_desk_deploy root@193.233.246.179

cd /opt/risk-desk
docker compose ps
docker compose logs -f --tail 100 app
docker compose restart app
```

Сбросить данные к seed (осторожно, удалит изменения):

```bash
cd /opt/risk-desk
docker compose -f compose.yaml -f compose.sso.yaml down -v
docker compose -f compose.yaml -f compose.sso.yaml up -d --build
```

После сброса пароль панели снова `admin123` (из `.env`), а realm Keycloak
переимпортируется из `deploy/keycloak/risk-desk-realm.json`.

## Вход по QR (без пароля)

На слайде и в `docs/screenshots/15-qr-demo.png` лежит QR, который открывает
`/api/v1/auth/demo?token=…`: сервер проверяет токен, ставит сессию и редиректит
в панель. Пароль не нужен.

- Токен: `/opt/risk-desk/.env`, `DEMO_LOGIN_TOKEN` (уже задан).
- Перевыпустить QR после смены токена:

  ```bash
  .venv/bin/python scripts/demo_qr.py --token "$(cat /tmp/demo_login_token.txt)"
  ```

  (нужны `qrcode` и `pillow`; ссылку и токен скрипт печатает сам).
- Отключить вход по QR: удалить значение `DEMO_LOGIN_TOKEN` из `.env` и перезапустить
  контейнер — эндпоинт начнёт отдавать 404.
- Неверный токен — 401. Токен виден в логах доступа, поэтому после защиты его
  лучше убрать вместе со стендом.

## Ограничения и безопасность

- **HTTPS нет** — стенд работает по `http://`. Для демо это допустимо, реальные
  данные клиентов туда не загружайте.
- Пароль администратора панели — `admin123` (демо, совпадает с подсказкой на экране
  входа). Пароль Keycloak-админа — в `/opt/risk-desk/.env` (`KC_ADMIN_PASSWORD`).
  Стенд публичный: не храните на нём реальные данные и не считайте его защищённым.
- **Пароль root был передан в чате** — после защиты смените его (`passwd`) или
  переустановите сервер.
- Keycloak на стенде **установлен** (порт 8081, ~500 МБ): SSO доступен и снаружи,
  и локально. Требование HTTPS у master-realm снимает скрипт деплоя.
- Срок сервера — примерно до **26 октября 2026**. После окончания оплаты ссылка
  перестанет открываться; локальный запуск из README продолжит работать.

## Если стенд недоступен

1. `curl -s http://193.233.246.179:8000/healthz` — должен вернуть `{"status":"ok"}`.
2. Если нет ответа — проверить сервер в панели Aéza (запущен ли, не истёк ли срок).
3. Если сервер жив, а приложение нет:

   ```bash
   ssh -i ~/.ssh/risk_desk_deploy root@193.233.246.179 \
     'cd /opt/risk-desk && docker compose ps && docker compose logs --tail 50 app'
   ```
