## 0. Принцип

**Сначала приёмка — потом красота.** Жюри не примет решение, если не работает
хотя бы один обязательный пункт. Поэтому порядок такой:

1. Данные и расчёт (score + деньги).
2. API и панель, которые показывают расчёт.
3. Настройки, живое обновление, метрики, Docker, auth.
4. Графики, OIDC, Grafana — только если всё выше готово и отрепетировано.

Правило: **любая фича, которая не входит в критерии приёмки, не начинается,
пока чек-лист приёмки не закрыт на 100%.**

### Технический старт
- [ ] `git init`, структура папок, `.gitignore`, `.env.example`.
- [ ] `compose.yaml` с hello-world: backend `/healthz` + frontend-заглушка.

**Выход из 2 часов:** запускается пустой compose, данные лежат, схема известна,
контракт согласован, роли распределены.

## 2. Фазы (48 часов)

| Фаза | Время | Цель | Владелец | Готово, когда |
|---|---|---|---|---|
| 0. Данные и контракт | T+0…2 | Схема, seed, compose, API-контракт | капитан + data | `compose up`, данные грузятся |
| 1. Ядро расчёта | T+2…10 | Признаки, score, деньги, snapshot, settings | backend | unit-тесты на формулу, `/customers` отдаёт оценки |
| 2. Панель | T+6…16 | Логин, дашборд, таблица, карточка, настройки | frontend | можно кликнуть полный сценарий |
| 3. Живость и метрики | T+12…22 | SSE, пересчёт, `/metrics`, unknown-состояния | backend + frontend | изменение веса видно без reload |
| 4. Сборка | T+20…30 | Docker, README, OpenAPI, график, UX | все | чистая машина запускается по README |
| 5. Закалка | T+28…38 | Тесты, баги, демо-данные, репетиция | QA + все | демо проходит 3 раза без падений |
| 6. Финал | T+38…46 | Заморозка, питч, бэкап, сдача | капитан | решение отправлено за 2 часа до дедлайна |

Параллельность: backend и frontend стартуют одновременно после контракта;
frontend первые часы работает на моках, потом переключается на реальный API.

## 4. Роли

| Роль | Зона | Кто (заполнить) |
|---|---|---|
| Капитан / PM / QA | приёмка, демо, питч, разблокировка, тайминг | |
| Backend / model | ядро расчёта, API, auth, БД, метрики | |
| Frontend | панель, таблица, настройки, SSE, UX | |
| Data / analyst | данные, seed, проверка модели, демо-кейсы, согласованность цифр | |
| DevOps / docs | Docker, README, OpenAPI, тесты, чистая машина | |

Если вас трое: backend+model, frontend, капитан+data+QA (он же питч).
Если двое: один backend+infra, второй frontend+UX; данные и модель делаете вместе.

**Правило капитана:** каждые 4 часа сверять статус с чек-листом приёмки,
а не с «ощущением прогресса».

## 5. Ритм

- **Kickoff 45 мин:** роли, стек, контракт, дедлайн.
- **Синк каждые 4 часа, 15 мин:** что готово / что блокирует / что режем.
- **Демо каждые 8 часов:** только по сценарию жюри, на чистой машине.
- **T−6 ч: заморозка фич.** Дальше только баги, тексты, демо.
- **T−3 ч: генеральная репетиция** с таймером, два раза.
- **T−2 ч: отправка.** Не в последние 10 минут.

Сон: минимум один 4–6-часовой блок на человека. Уставший капитан на защите
стоит дороже одной недоделанной фичи.

## 6. Демо-сценарий (репетировать дословно)

1. Чистая машина, `docker compose up`, открыть `http://localhost:8000`.
2. Неверный пароль → ошибка. Верный → дашборд.
3. Дашборд: ожидаемые потери, gross MRR, клиенты по уровням, график.
4. Топ-таблица: сортировка по балансу ↑/↓, фильтр «высокий риск».
5. Клиент: score 75, причины, услуги, вклад в потери.
6. Меняем вес `funds_gap` → цифры и порядок меняются **без reload**.
7. `docker compose restart` → настройки на месте.
8. `curl /metrics` → цифры совпадают с UI.
9. Загружаем снапшот с пополненным балансом → score падает.
10. `curl` без cookie → 401; Swagger; README; diff «как добавить признак».

Тайминг: 5 минут демо + 3 минуты вопросы. Репетировать с секундомером.

## 7. Риски

| Риск | Вероятность | Удар | Что делаем |
|---|---|---|---|
| Не скачали данные (капча/пароль) | средняя | высокий | скачать вручную в первый час, seed в репо |
| Раздули scope (OIDC, Grafana, ML) | высокая | высокий | P0-гейт, заморозка за 6 ч |
| SSE не работает на защите | средняя | высокий | polling каждые 5 с как фолбэк, переключатель |
| Настройки не пережили рестарт | средняя | высокий | хранить в БД, тест «restart» в чек-листе |
| Сортировка только по странице | высокая | средний | сортировка в SQL/на сервере, тест на 2 страницах |
| Цифры UI ≠ `/metrics` | средняя | высокий | один кэш результатов, метрики из него же |
| Docker не собирается на чужой машине | средняя | высокий | тест на чистом клоне, без локальных путей |
| Забыли «нет оценки» | высокая | средний | тест-кейс: клиент без услуг |
| Ошибка в копейках/евро | высокая | высокий | integer cents, Decimal, unit-тест |
| Дата/таймзона `expiresAt` | средняя | средний | всё в UTC, дни считаем аккуратно |
| Забыли комментарий `Aéza` | средняя | высокий | пункт в чек-листе сдачи |
| Заболел участник | низкая | высокий | кросс-ревью, README, демо у капитана |
